# Orchestrate parallel Work Items above serial Agent Runtimes

Coda keeps `@coda/agent` serial and introduces one Workspace-scoped Work Coordinator inside the headless Runtime Module. The Coordinator owns a durable Work Graph, bounded scheduling, cancellation propagation, Work Journal persistence, Worker Runtime and Session leases, structured Work Results, and Workspace Publication. Every Work Item owns exactly one Worker Runtime and one Session lease; no Session or transcript is shared between concurrent Work Items. Runtime teardown owns the complete opening-to-closed epoch: it cancels and joins in-flight construction, closes any materialized Runtime, invalidates retained Observations, and closes the Session before deleting its lease; an unconfirmed close quarantines the lease instead of permitting reuse. A durable Session may be resumed by a later Work Graph only after its earlier Work Item releases that lease. During recovery the Session Adapter may lazily reopen a missing durable root Session by identity; child Sessions that never started remain reconstructible empty private records.

The public headless Interface moves above individual Agent Runtime instances and controls Work Graph and Work Item identities rather than Runtime identities. Its external shape is a closed command algebra, an isolated Observation stream, and idempotent close. Instance-level Agent Runtime construction, input queues, Prepared Run capabilities, and Context Window controllers become private Implementation. This intentionally removes `openAgentRuntime`, `openCodingAgentRuntime`, `CodingAgentRuntime`, and their compatibility surface instead of layering a Runtime pool over them.

Workspace concurrency is delegated through one real Seam with Direct and Git worktree Adapters. Production composition selects Git worktrees for Git Workspaces and falls back to Direct for non-Git Workspaces; construction can replace that policy through the same Adapter factory. The Direct Adapter permits concurrent read-only Tool Invocations but serializes write or unknown effects across the Workspace; Shell and background Process effects remain exclusive until quiescent. The Git worktree Adapter gives write-capable Work Items derived Workspace Placements. Every accepted item receives an immutable Workspace-wide Publication order, while each Adapter-owned target sequencer serializes the complete fingerprint/check/apply transaction for that target; different targets remain independent. A Placement records its target identity and each successful Publication advances that identity durably, so recovery rejects external source changes instead of adopting the process-start state; an unclosed Publication taints the target until explicitly reconciled. Completion order therefore cannot determine cross-Graph source Publication. A worktree is data placement, not a sandbox, and cancellation never claims to roll back effects that already occurred.

Session persistence remains the fatal ordered barrier for one Worker Runtime. Work Journal persistence is the fatal ordered barrier for orchestration, and a durable `batch_accepted` record is the command's linearization point: later bookkeeping cannot turn that receipt into a rejection. External resources are only reserved before that point; their irreversible commit and an `input_resources_settled` record happen afterward, before input becomes visible to a Worker. Unknown or failed settlement interrupts the affected Work instead of replaying input. If the shared journal fails, the Coordinator fail-stops every accepted Work Item lacking a journaled result and may return a process-local result only with `durability: unknown`; every such Item, including pending, ready, and terminal-without-result Items, remains in `unknownWork` because recovery may execute or reclassify it. Only a journaled result has `durability: confirmed`. A Coordinator-owned mutation fence serializes live-state revalidation, accepted in-memory mutation, terminal lifecycle boundaries, Publication start, and result settlement without serializing Model or Tool execution. UI, JSON, evaluation, telemetry, and Extension projections consume only the public `observe()` stream and cannot stop Tool or Model effects. A completion repair that can submit Steering is classified separately as ordered Worker Control: it runs only after the lifecycle event is journaled, may delay later Agent progression until its Work Item command is accepted, and detaches on failure without becoming a persistence barrier. A Work Graph recovered with an unclosed Tool Invocation, input-resource settlement, or Publication is marked interrupted and is never replayed automatically.

This supersedes the public-Interface and caller-composition clauses of ADR-0043 while preserving its serial Agent, atomic Prepared Run, instance-local desired configuration, dependency direction, and deterministic per-Run snapshot decisions. The alternatives rejected are making Agent itself concurrent, sharing one Session across workers, treating `AgentTool.parallelSafe` as a Workspace consistency contract, and adding a pass-through map of public `CodingAgentRuntime` instances.
